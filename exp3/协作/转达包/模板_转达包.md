# 转达包模板（E 用，不发给评审人）

> 用途：评审人=豆包时，每次送审生成一个自足文本包。单包 ≤ 6000 字；超了拆包并标“第 1/N 包”。
> 命名：`协作/转达包/G<n>_发给豆包.md`（P0 轮为 `P0_发给豆包.md`）。
> 生成后必须自检：§3 每条判据都有对应证据行；§5 问题 ≤6 条且都能靠本包内容回答。

---

## 1. 抬头（固定 4 行）

```
门禁：G<n>（覆盖阶段 S<x>–S<y>）　轮次：第 <r> 轮
送审时间：YYYY-MM-DD HH:MM　提交：<短哈希>
判据来源：协作/指示/P0_任务书.md §3（阶段 S<x>…S<y>）
材料范围：本包自足，你无需访问仓库
```

## 2. 角色与规则（每包重复，≤120 字）

```
你是本项目的独立评审人。只依据本包材料评审，不臆测未提供的内容。
每条结论必须引用本包中的证据编号（E1、E2…）或判据编号（J1、J2…）。
凡需读盘/跑命令才能判断的事项，写“需证据补充：<具体要什么>”，不要直接判定通过或失败。
你不写代码，只判定“是否达标”与“还缺什么”。
```

## 3. 本轮判据（表格：编号 / 判据 / 来源）

| 编号 | 判据（命令级或文件级） | 来源 |
|---|---|---|
| J1 | | 任务书 §3 S<x> |

## 4. 逐条证据（表格：编号 / 命令 / 输出关键行 / 对应判据）

| 编号 | 命令 | 输出（原样摘录，含数字） | 对应 |
|---|---|---|---|
| E1 | `pytest -q` | `42 passed in 3.1s` | J3 |

> 禁止只写“测试通过”“运行正常”。摘录必须能被评审人核对数字。

## 5. 材料摘录（只给判断所需的最小片段）

- 代码：只给函数签名 + 关键行（`path:line`），不给整文件
- 文档：只给结论段，不给全文
- 数据：表名 + 列名清单，DDL 只给关键约束

## 6. 请评审人回答（编号问题，≤6 条）

1. 判据是否可验证？哪条不可验证，改成什么？
2. 证据是否足以支撑结论？哪条证据不足，需要补什么？
3. 范围与工期是否匹配？应砍什么？
4. 有无会直接导致不及格或返工的遗漏？
5. 是否批准进入下一门禁？附 ≤3 条约束。

## 7. 输出格式（要求评审人照此回复）

```
判定：通过 / 有条件通过 / 不通过
一、判据核对：J1 满足/部分/不满足（依据 E?）
二、意见：编号 P0-R2-01 起，级别（必修/应修/建议），问题，要求，依据
三、需证据补充：<清单>
四、变更裁定：CR-xx 各项 批准/驳回 + 理由
五、授权：允许进入 G<n+1> / 暂不授权，约束 ≤3 条
```

## 8. 回填（E 用）

豆包回复整段存入 `评审记录/G<n>_第<r>轮.md`，抬头加 `来源：豆包（人工转达，未读文件）`；意见编号原样保留；E 的异议另起“异议”段，不删改原文。
