## 三、执行者方案要点

1. **技术栈**：Python 3.12 + Tkinter（标准库 GUI）+ SQLite（标准库数据库），**零第三方运行时依赖**；仅开发期用 pylint、coverage。
2. **分层**：表现层（ui）/ 应用层（application）/ 领域层（domain）/ 基础设施层（infrastructure），类名与实验二类图逐字对齐（12 实体 + 1 状态枚举 + 3 领域服务 + 3 仓储接口 = 19 个符号），用脚本 `check_uml_sync.py` 自动比对。
3. **数据**：单文件 SQLite，12 张表（用户、酒店、房型、每日库存、每日价格、订单、订单逐晚、幂等键、入住记录、审计日志、通知、节假日）。
4. **不超卖机制**：单写者 + `BEGIN IMMEDIATE` 显式事务（连接 `isolation_level=None`、显式 `busy_timeout`），事务内“复核重复预订 → 逐日扣减可用量 → 建单 + 逐晚快照 + 幂等键”原子完成；配合部分唯一索引兜底。
5. **三条关键链路**：下单锁库存 / 超时未支付自动取消并回补 / 改期“先占新日期、成功后再放旧日期”，失败整单回滚。
6. **界面**：10 屏（登录注册、搜索、结果列表、房型详情下单、我的订单、订单详情、酒店订单台、酒店库存价格、平台管理、报表），四角色权限生效。
7. **代码量口径**：`code/app/` 与 `code/tests/` **分列统计**，主口径只算 `app/`（比课程要求更严）；“有效行”= 扣空行、纯注释、docstring；统计脚本与逐文件 CSV 入库。
8. **阶段划分**：S0 骨架与环境 → S1 数据底座 → S2 领域层 → S3 仓储与核心业务 → S4 履约调度 → S5 报表对账 → S6 界面 → S7 质量门禁 → S8 Git 与远程 → S9 报告与打包。
