# 豆包评审操作规程（P4 已定：评审人 = 豆包，人工转达）

> 结论：豆包**不能读盘、不能跑命令**，所以“互联”靠**转达包 + 人工粘贴**。你每次只需做两件事：把包粘给豆包、把回复粘回来。

## 一、一次门禁的完整动作（约 3 分钟人工）

```
我生成 协作/转达包/G<n>_发给豆包.md
        ↓  你整包复制
豆包（同一个对话窗口即可，不必新开）
        ↓  它回复判定 + 意见
你整段复制回来贴给我
        ↓
我原样存档为 评审记录/G<n>_第<r>轮.md（标注“来源：豆包，人工转达”）
        ↓
我按必修项整改，再出 G<n> 第 2 轮转达包（只含整改项 + 证据）
```

## 二、粘给豆包时的三句话（可直接用）

1. 第一包：`这是第 <n> 个门禁的评审材料，请按材料末尾的输出格式回复。`
2. 若它说“我看不到代码”：
   `你不需要看代码，材料里已给出判据与证据；你只判“证据是否足以支撑结论”，缺什么就写“需证据补充”。`
3. 若它开始给实现建议：
   `请不要写实现代码，只给判定与整改要求。`

## 三、它的回复怎么用

| 它的输出 | 我的处理 |
|---|---|
| 判定 + 判据核对表 + 编号意见 | 原样入库；必修项进整改清单，逐条回应在 `交付/G<n>/整改回应.md` |
| “需证据补充：xxx” | 我补跑命令、生成增量包 `G<n>_第<r>轮_补充.md`，你只需粘这一小包 |
| 与证据矛盾（如要求改已实测通过的判据） | 我不自行改判；写“异议”段 + 证据，交你裁决（记决策日志） |
| 判定“不通过” | 我按返工范围重做，再出下一轮包；同门禁最多 2 轮整改，第 3 轮升级为范围重定 |

## 四、提高它评审质量的三条实操

1. **给数字，不给形容词**：证据段写 `42 passed in 3.1s`、`app/ 有效行 1834`、`pylint 9.24/10`，它才有东西可挑。
2. **给编号**：判据 J1…、证据 E1…、意见 P0-R2-01…，它引用编号时不会跑偏。
3. **限定输出格式**：包尾固定要求“判定 / 判据核对 / 编号意见 / 需证据补充 / 授权”，否则它会写成散文，无法归档。

## 五、内部预检（可选，不计门禁）

送豆包之前，我可以先让本地子代理做一次“证据与判据是否对得上”的预检（不写评审记录），目的是**减少豆包往返次数**——每次往返大约值半天工期。是否启用由你说。

## 六、能力边界（写进报告也有用）

- 豆包能判：方案是否自洽、判据是否可验证、证据是否充分、工期是否现实、遗漏与风险。
- 豆包不能判：代码是否真能跑、并发是否真不超卖、界面是否真能点——这些只能由**命令输出**背书，它判的是“证据链是否闭合”。
- 因此每包证据段必须是**真实命令 + 原始输出摘录**，我会逐条跑过再贴，绝不写“测试通过”这种空话。
