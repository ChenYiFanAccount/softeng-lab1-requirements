## 5. 偏差与"设计要求 vs 实现口径"登记

| # | 设计要求（exp2 基线 / UML） | 实现口径 | 原因 | 后续承接 |
|---|---|---|---|---|
| D1 | `notification_record` 字段按 UML 或按数据设计（两者不完全一致） | 取**并集**：`id/booking_id/channel(IN_APP,SMS)/content_summary/result/notified_at` | D-017 第 1 项，R 已在 S0 第 1 轮追认（追加"须回改 UML 升 v1.2"） | **exp2 只读**，无法改 `exp2/UML/UML类图.puml`；改在 `code/docs/uml_map.md` 与报告差异表登记，S2 交付时一并说明 |
| D2 | U6"同时段最多一单" | 部分唯一索引只拦**起止日完全相同**；重叠区间（如 3/1–3/3 与 3/2–3/4）由应用层在事务内按"房型×日期"复核 | SQLite 唯一索引表达不了区间不重叠 | S3 下单/改期必须带该复核；`S1_05_constraints.txt` 有"重叠日期不被索引拦"用例把边界钉死 |
| D3 | `可售间数 ≤ 总房量` | 行内 CHECK 只能表达 `occupied ≤ available`，`available ≤ total_rooms` 由建库/种子/应用层保证 | CHECK 不能跨表引用 `room_type.total_rooms` | S4 库存维护用例补断言；报告差异表登记 |
| D4 | 每日价格 | 独立表 `room_price(room_type_id, stay_date, unit_price_cents)`，与 `room_inventory` 分开 | 价格与库存变更频率、权限不同（酒店改价不改量） | 已在 S1 落地，S5 报表直接联表 |
| D5 | 金额类型 | 一律 `INTEGER` 分（`*_cents`），禁止浮点 | S2-5 判据要求 `float(`/`round(` 命中 0；浮点金额不可对账 | S5 对账用整数比较，无容差 |
| D6 | 枚举取值 | 存大写英文码（`PENDING`/`CONFIRMED`/…），界面层做中英映射 | 便于约束、日志与测试断言；中文只出现在 UI | S6 建映射表，禁在 SQL 里写中文 |
