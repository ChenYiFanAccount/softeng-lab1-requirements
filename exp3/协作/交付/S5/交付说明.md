## 9. 第 1 轮整改（G3-R1-01 / G3-R1-02）

### 9.1 G3-R1-01（必修）：退房单被排除出营收与对账右侧

**缺陷现象（R 实测）**：订单在 `PENDING`、`CHECKED_IN` 时，2027-03-01 / 03-02 营收各 60000 且 `diff=0`；一旦 `CHECKED_OUT`，两行营收全部消失，对账 `diff=4`，并输出两行 `ALERT … inventory=2 orders=0 diff=2 bookings=-`。

**根因**：`code/app/infrastructure/db/report_repository.py` 的 `ACTIVE_VALUES` 由 `ACTIVE_STATUSES`（待确认/已确认/已入住）派生，却被营收、入住率、对账右侧三处共用。而 `CHECKED_OUT` 只改状态、**不释放占用**（释放只发生在 `RELEASING_EVENTS`：取消/拒单/超时/未入住），所以右侧少了退房单 → 每单误报 `diff=2`，营收在退房瞬间归零。

**修法（最小改动，两套集合）**：

| 落点 | 改动 |
|---|---|
| `report_repository.py` | 删 `ACTIVE_VALUES/ACTIVE_PLACEHOLDERS`；新增 `REVENUE_STATUSES = (PENDING, CONFIRMED, CHECKED_IN, CHECKED_OUT)` 与 `REVENUE_VALUES / REVENUE_PLACEHOLDERS`；`OCCUPYING_VALUES = REVENUE_VALUES` 与 `OCCUPYING_PLACEHOLDERS`；`sold_room_nights` / `revenue_by_day` 用 `REVENUE_*`，`order_side` 用 `OCCUPYING_*`（注释写明"退房不释放占用，右侧排除会每单误报"） |
| `report_service.py` | 模块注释口径改为"只算成交过的订单（含**已退房**）；已取消、未入住不计（库存已回补）"，并写明历史原因 |
| `reconcile_service.py` | `alert_line()` 在无关联订单时写 `bookings=NONE(无有效订单，库存多占)`；`orders_occupied > 0` 但无单号时写 `NONE(订单缺订单号，数据异常)`；不再出现裸 `bookings=-` |

**补的 3 条用例**（`S5_10_g3r101_cases.txt` 逐条单跑证据）：

| # | 用例 | 断言要点 |
|---|---|---|
| 1 | `test_退房后营收与独立SQL一致且不为零` | 退房后状态 `CHECKED_OUT`；`revenue_by_day` 与裸 SQL（含 `'CHECKED_OUT'`）逐日相等；`actual["2027-03-05"] == 30000`；总额 > 0；`sold_room_nights("2027-03-05") == 1` |
| 2 | `test_退房后对账diff等于零` | `CHECK_IN`→`CHECK_OUT` 后 `occupied("2027-03-01") == 2`（不释放）；`is_clean`、`diff=0`、含 `status=OK`、无 `ALERT` |
| 3 | `test_告警行不得出现裸bookings减号` | 03-04 无订单却占 1 间 → 文本不含 `bookings=-`，含 `bookings=NONE(无有效订单，库存多占)`，且含日期 |

**`--demo` 增加"含已完成订单的平账"**：`demo()` 在已确认单平账之后，用 `complete_stay(bookings, booking_no, staff)` 把该单走完 `CHECK_IN → CHECK_OUT`，再跑一次对账（`diff=0 status=OK`）并打印 `revenue stay_date=2027-03-01 cents=60000` / `2027-03-02 cents=60000` / `revenue_total_cents=120000`，最后才做两处人为篡改。这样"退房后仍平账、营收不为零"在演示里也能直接看到。

### 9.2 G3-R1-02（应修）：期望值不得用被测函数自证

`code/tests/test_report_matches_sql.py` 原第 189 行用被测模块的 `permille()` 计算期望入住率。整改后：

- 期望值改为字面量算术 `sold_nights * 1000 // capacity_of_day`（注释标注 `G3-R1-02`）；
- 测试文件不再从被测模块导入 `permille`；
- 营收期望值仍是裸 SQL（含 `'CHECKED_OUT'`），入住率期望值是纯算术，两者都不再经过被测实现。
