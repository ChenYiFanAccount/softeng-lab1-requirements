## C. 关键决策（含理由与代价，报告可直接引用）

### C.1 语言与技术栈：**Python 3.12 + Tkinter + SQLite（标准库三件套）**

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Python + Tkinter + SQLite** | 零第三方运行时依赖（venv 里已验证 tkinter 8.6 / sqlite3 可用）；桌面 GUI 满足"后续实验要对程序分析与测试"的建议；`unittest` 内建；pylint 生态成熟；1500 行在 10 模块规模下自然达标 | Tkinter 观感朴素，复杂表格需手工封装；GIL 下并发测试要用多线程 + 事务而非多进程 | **采用** |
| Java + JavaFX/Swing | 强类型、checkstyle 规范明确 | 环境搭建与打包成本高（JDK/JavaFX 模块化），6 天内 GUI 工作量大 | 否 |
| C++ + Qt | 性能与"编译"证据最硬 | Qt 部署与内存管理成本最高，单元测试框架另配 | 否 |
| Python + PySide6 | GUI 观感好 | 需联网装轮子（约 100MB+），打包体积大，且 `.ui` 自动生成代码**不计入**行数，等于白干 | 否 |

**代价与对策**：Tkinter 无现成数据网格 → 用 `ttk.Treeview` 封装一个可复用表格组件；Python 无"编译" → 用 `compileall` + 可选 PyInstaller 单文件打包作为构建证据。

### C.2 架构：**4 层 + 10 模块纵切，类名与类图逐字对齐**

- 分层照 `02_模块划分与交互.md` §1：表现层（GUI）/ 应用服务层（用例编排、事务、幂等、权限）/ 领域层（实体、状态机、库存与计价规则、**仓储接口**）/ 数据访问层（SQLite 实现仓储）。
- 依赖倒置照类图：领域层定义 `BookingRepository`、`InventoryRepository`、`AuditLogRepository` 三个接口，数据访问层实现；**唯一的反向箭头**，启动时注入。
- 模块编号 M1–M10 直接作为包内模块切片，报告"模块→目录→类"三列可对齐，避免"图表两张皮"。

### C.3 存储：**单文件 SQLite，12 张表，事务与唯一约束承载 REQ-019/REQ-014**

- 12 表照 `03_数据设计.md` §2：`user_account`、`hotel`、`room_type`、`room_inventory`、`room_price`、`booking`、`booking_night`、`idempotency_key`、`stay_record`、`audit_log`、`notification_record`、`holiday_calendar`。
- 关键不变量落库：`room_inventory` 的 `(房型, 日期)` 唯一；`booking_night` 的 `(订单, 日期)` 唯一；`idempotency_key` 主键唯一；有效订单的"同顾客+同酒店+同时段+同房型"用**部分唯一索引**（SQLite 支持 `WHERE` 条件索引）。

- **完成判据**：`git status` 干净可提交；`python -c "import tkinter, sqlite3"` 通过；pylint 可执行并输出版本。

### S1 骨架 + 数据库 + 种子数据（0.7 天）

- **做什么**：12 张表的 DDL（含唯一/部分唯一索引、外键、`CHECK` 约束）；连接与事务封装（`BEGIN IMMEDIATE`、`foreign_keys=ON`、WAL）；种子脚本：3 家酒店、8 个房型、90 天逐日库存与价格、4 类角色账号、节假日若干。
- **怎么做**：DDL 与 `03_数据设计.md` 逐字段对齐；种子数据用固定随机种子保证可复现；`docs/` 存一份"表→REQ→约束"对照。
- **完成判据**：空库一键建库 + 灌种子 < 5 秒；`PRAGMA integrity_check` 通过；能查出"某房型某区间每日余量"。

### S2 领域层：实体、状态机、库存、计价、取消政策（1 天）

- **做什么**：13 个实体（dataclass）+ `BookingStatus` 枚举；`BookingStateMachine`（6 状态 / 8 条边 / 5 条禁止，转移表驱动，拒绝时给原因）；`RoomInventory` 的余量与可占用规则；逐晚计价（`Σ 单价快照 × 间数`）；取消政策（普通日 vs 节假日、不可取消区间）；三个仓储接口。
- **怎么做**：状态机用"（当前状态, 事件）→ 目标状态"的显式表，禁止 if-else 长链；日期一律用"半开区间 `[入住日, 退房日)`"，逐晚展开；金额用 `Decimal` 或整数分，禁止浮点。
- **完成判据**：单测覆盖 8 条允许边 + 5 条禁止边 + 跨状态跳跃；余量边界（0 间、恰好等于余量、超出）全部有用例；`python -m unittest` 全绿。

### S3 仓储与应用服务：账号权限 / 酒店房型 / 库存价格 / 搜索 / 下单（1.2 天）

- **做什么**：SQLite 仓储实现；`M1` 注册登录（加盐哈希、连续 5 次失败锁定 10 分钟、会话与角色、数据隔离）、`M2` 酒店与房型维护 + 入驻审核、`M3` 每日库存与价格维护（改总房量钳制、按日调整可售不得低于占用）、`M4` 多条件搜索（区间每日余量取最小、任一日无房即排除）、`M5` 下单事务（幂等键 → 锁内复核重复预订 → 逐日占用 → 建单 + 快照 → 待确认）、改期（先占新后放旧、整单原子）、取消（政策判定 + 回补）。
- **怎么做**：应用服务只编排，规则留在领域层；权限校验统一入口（未登录 401、越权 403 且不泄露对象存在性）；所有"改状态"必须过状态机；失败一律抛领域异常并带错误码。
- **完成判据**：三条链路可端到端跑通（脚本或测试驱动）；并发抢最后一间房：N 线程仅 1 成功、其余库存不足、无半张订单（REQ-019）；同幂等键重复提交只出一张单（REQ-014）。

### S4 履约与调度：确认/拒单/入住/退房/no-show + 超时任务 + 审计 + 通知（0.8 天）

- **做什么**：`M6` 酒店确认/拒单（必填原因）/核验入住/退房/no-show（23:59 前可标，之后按钮失效）；`M7` 取消执行、酒店原因取消（停业/超售）与协商留痕；`M9` 审计只追加（含 403/409 也记一条）；`M10` 后台线程按可配置阈值扫描超时待确认单（默认 30 分钟，演示可调到 1–2 分钟），同事务置取消 + 回补，重复扫描不重复释放。
- **怎么做**：调度器用单线程 + 可中断 sleep，退出时干净停止；每个动作写 `stay_record`；审计含前状态/后状态/原因/来源。
- **完成判据**：超时单在阈值后被自动取消且库存回补，再扫一次不重复回补；no-show 跨零点的兜底规则可被测试时间注入验证（时钟抽象成可替换的 `Clock`）。

### S5 报表 / 对账 / 配置（0.4 天）

- **做什么**：`M8` 入住率 = 已住间夜 ÷ 可售间夜（按每日挂牌量），订单量与取消率，按日/月、本店/全平台；`M10` 对账任务（占用数与有效订单汇总比对，只告警不自动改）；配置中心（超时阈值、一期开关）。
- **完成判据**：报表数字与手工 SQL 对得上（至少 2 组用例）；对账在人为造差异时能告警。

## F. 大模型辅助规范（报告 R3–R5 的素材来源）

### F.1 工作流（照手册建议的"需求 → 存根 + 规约 → 代码"）

1. **喂规格**：把 REQ 原文 + `03_数据设计.md` 表结构 + 类图签名一起给，而不是只说"写个酒店系统"。
2. **先存根**：让模型只产出类/函数签名 + 规约（前置条件、后置条件、异常），人工审一遍再要实现。
3. **小步生成**：一次一个类/一个用例，避免一次生成 500 行无法审。
4. **逐行审**：每段代码人工过一遍，标注"采纳/改写/废弃"。
5. **测试先行**：让模型按规约生成单测，人判断断言是否正确（模型常写"能跑通"的弱断言）。

### F.2 记录格式（每次交互一条，存 `code/docs/ai/`）

| 字段 | 要求 |
|---|---|
| 场景 | 如"生成 BookingStateMachine 转移表" |
| 输入 | 关键 prompt 原文（可脱敏） |
| 输出摘要 | 模型给了什么，多少行 |
| 问题 | 不符合预期之处（越权改状态、漏回滚、浮点金额、弱断言…） |
| 人工处理 | 改 prompt / 补规格 / 手写替换，附 diff 位置 |
| 结论 | 采纳比例、教训 |

### F.3 Git 留痕（报告 R6 与"人工修改"证据）

- 提交信息前缀：`[AI]`（模型直出且仅做机械修改）、`[AI+H]`（模型出稿 + 人工实质修改）、`[H]`（纯人工）。
- 关键提交在描述里写"人工修改点"，让 `git log` 本身能证明"读过每一行"。

### F.4 红线

- 不把 `pylint` 的 `# pylint: disable` 当整改手段（除非写明理由并计数）。
- 不把模型生成的测试当"验证通过"的充分证据，断言要人工核。
- 报告正文不由模型起草（手册禁令）。
