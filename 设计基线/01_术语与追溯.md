## 2. 订单状态字典

**六个状态**（界面与图统一用这 6 个中文词）

| 状态 | 英文标识 | 含义 | 是否占用库存 |
|---|---|---|---|
| 待确认 | PENDING | 已下单、库存已锁定，等酒店处理 | 是 |
| 已确认 | CONFIRMED | 酒店已确认 | 是 |
| 已入住 | CHECKED_IN | 已办理入住 | 是 |
| 已退房 | CHECKED_OUT | 已办理退房，订单完结 | 否 |
| 已取消 | CANCELLED | 顾客取消 / 拒单 / 超时 / 停业 / 强制取消 | 否（即时回补） |
| 未入住 | NO_SHOW | 已确认但顾客未到店 | 否 |

**允许的 7 条转换（含触发者与守卫条件）**

| # | 起始 → 目标 | 触 发 | 守卫条件 |
|---|---|---|---|
| T1 | 待确认 → 已确认 | 酒店工作人员确认 | 订单仍为待确认且未超时 |
| T2 | 待确认 → 已取消 | 酒店拒单（须原因） | 同上 |
| T3 | 待确认 → 已取消 | 系统定时任务 | 超过确认阈值（默认 30 分钟，可配置） |
| T4 | 已确认 → 已入住 | 酒店核验入住 | 凭订单号或手机号核验通过 |
| T5 | 已确认 → 已入住 | 系统次日默认置入 | 入住日 23:59 前未标记且未到店 |
| T6 | 已确认 → 未入住 | 酒店标记 no-show | 入住日 23:59 前 |
| T7 | 已确认 → 已取消 | 顾客按取消政策 / 酒店停业超售 / 管理员强制 | 前两者须政策允许或停业事实成立；管理员须填原因并二次确认 |
| T8 | 已入住 → 已退房 | 酒店办理退房 | 订单为已入住 |

> 说明：T2 与 T3 目标相同、触发者不同，图上必须**分开成两条边**，不要合并成"拒单/超时"一条。

**禁止的 5 条转换（图上以注释块明示"一律拒绝"）**

| 禁止转换 | 理由 |
|---|---|
| 已入住 → 已取消 | 费用与库存已实际发生 |
| 已退房 → 已取消 | 订单已完结 |
| 已取消 → 已确认 | 库存已回补，恢复会造成重复占用 |
| 已入住 → 已确认 | 状态回退 |
| 已退房 → 已入住 | 状态回退 |

统一处置：非法转换与跨状态跳跃一律拒绝（HTTP 409 语义），**状态不变**，写审计日志。

| 用户与入驻审核 | — | — | — | ✓ |
| 节假日日期表维护 | — | — | — | ✓ |

## 5. 变更纪律

1. REQ 编号沿用实验一，**不重排、不新增自造编号**；若实验中补充设计项，记作 `D-xx`（设计项，非需求），单列一节，避免污染需求编号。
2. 术语表新增条目必须先登记于此，再出现在图或界面中。
3. 状态名、状态转换一旦变动，须同步更新本文件第 2 节、状态图、界面 07/08/10/13 四处，缺一处即视为不一致。
