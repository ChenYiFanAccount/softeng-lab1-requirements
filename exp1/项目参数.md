## 5. 业务状态与转换（报告 2.3 节）

### 5.1 六个状态

| 状态 | 含义 | 是否占用库存 |
|---|---|---|
| 待确认 | 顾客已下单、库存已锁定，等酒店处理 | 是 |
| 已确认 | 酒店已确认预订 | 是 |
| 已入住 | 已办理入住 | 是 |
| 已退房 | 已办理退房，订单完结 | 否 |
| 已取消 | 顾客取消、酒店拒单/取消、超时未确认、停业取消 | 否（即时回补） |
| 未入住 | 已确认但顾客未到店（no-show） | 否 |

### 5.2 允许的转换（共 7 条）

| 起始 → 目标 | 触发者 | 依据 |
|---|---|---|
| 待确认 → 已确认 | 酒店工作人员确认 | REQ-007 |
| 待确认 → 已取消 | 酒店拒单／30 分钟超时未确认（系统） | REQ-007、REQ-005 |
| 已确认 → 已入住 | 酒店凭订单号或手机号核验入住 | REQ-013 |
| 已确认 → 已入住（系统默认） | 入住日 23:59 前未标记且未到店，系统次日置为已入住 | REQ-011 |
| 已确认 → 已取消 | 顾客按取消政策／酒店因停业或超售／管理员强制 | REQ-010、REQ-012、REQ-023 |
| 已确认 → 未入住 | 酒店在入住日 23:59 前标记 | REQ-011 |
| 已入住 → 已退房 | 酒店办理退房 | REQ-013 |

### 5.3 明确禁止的转换（报告须点明）

| 禁止的转换 | 理由 |
|---|---|
| 已入住 → 已取消 | 已实际入住，费用与库存已发生 |
| 已退房 → 已取消 | 订单已完结 |
| 已取消 → 已确认 | 库存已回补，恢复会造成重复占用 |
| 已入住 → 已确认 | 状态回退 |
| 已退房 → 已入住 | 状态回退 |

任何非法转换返回 409、订单状态不变，并写入审计日志（REQ-008）。跨状态跳跃（如待确认 → 已入住）同样一律拒绝。

## 6. 数据实体、关系与唯一性（报告 2.2 节）

| 实体 | 关键属性 | 关系 |
|---|---|---|
| 用户账号 | 角色（顾客／酒店工作人员／平台管理员）、手机号、口令哈希 | 顾客 1—N 订单 |
| 酒店 | 名称、地址、电话、简介、入驻审核状态 | 酒店 1—N 房型；酒店 1—N 订单 |
| 房型 | 名称、床型、面积、可住人数 | 房型 1—N 每日库存；1—N 每日价格 |
| 每日库存 | 房型 × 日期 → 可售间数 | 与订单占用逐日对应 |
| 每日价格 | 房型 × 日期 → 单价 | 下单时写入订单价格快照 |
| 订单 | 订单号、顾客、酒店、房型、间数、入住日、退房日、金额、状态、幂等键、取消原因 | 订单 N—1 房型；1—N 办理记录 |
| 入住／退房办理记录 | 订单号、操作人、时间、动作 | 从属于订单 |
| 节假日日期表 | 日期（平台统一维护） | 被 REQ-010 判定引用 |
| 操作日志 | 操作人、角色、时间、对象 ID、动作、变更前后状态 | 只追加、保留 180 天 |
| 通知记录 | 订单号、通知时间、协商结果 | 停业或酒店取消时生成 |

**不能重复的内容：**

1. 同一顾客 + 同一酒店 + 同一时段 + 同一房型，最多一条有效订单（有效指待确认／已确认／已入住）——REQ-014；
2. 同一幂等键只允许生成一张订单——REQ-014；
3. 同一房型同一天只有一条库存记录、一条价格记录——REQ-003、REQ-024；
4. 节假日日期表内日期不重复——REQ-027；酒店名称不重复——REQ-025。

**同步更新的规则：** 下单扣减、取消／超时／拒不回补、改期先占新后放旧且整单原子（REQ-005、REQ-009、REQ-019）；改价只影响新订单，历史订单按快照（REQ-006、REQ-024）；停售／停业只影响新订单，已确认订单保留（REQ-012）。

## 8. 异常与边界清单（报告 2.3 / 3 可引用）

| # | 异常场景 | 处理办法 | 依据 |
|---|---|---|---|
| 1 | 多人同时订最后一间房 | 仅第一个成功，其余返回库存不足且不产生订单；超卖次数必须为 0 | REQ-005、REQ-019 |
| 2 | 重复提交／重复预订 | 幂等键去重返回原订单；同顾客同酒店同时段同房型仅一条有效订单 | REQ-014 |
| 3 | 酒店 30 分钟未确认 | 系统定时任务自动取消并回补库存，顾客可见「超时未确认」 | REQ-005、REQ-015 |
| 4 | 改期撞新房源库存 | 整单失败，原订单与原库存不变 | REQ-009 |
| 5 | 落在不可取消区间 | 拒绝取消并提示原因 | REQ-010 |
| 6 | 停售／停业与已确认订单冲突 | 已确认订单保留，酒店协商取消并通知（记录通知时间与协商结果） | REQ-012、REQ-023 |
| 7 | no-show 跨零点未标记 | 系统次日置为已入住，记录标记人=系统、备注=系统默认 | REQ-011 |

| 9 | 酒店减房低于已售 | 拒绝该次修改并提示当前占用数 | REQ-003 |
| 10 | 越权访问他人订单／他店数据 | 返回 403 且不泄露目标是否存在 | REQ-020 |
| 11 | 库存扣减中断 | 整单回滚不产生半张订单；对账任务发现差异并告警 | REQ-019 |
| 12 | 区间内某日缺价 | 拒绝下单并提示缺失日期 | REQ-006、REQ-024 |
