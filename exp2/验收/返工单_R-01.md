## 1. 问题复述（一句话）

把"可售间数"定成"当日净剩余"，再用 `占用 = 总房量 − 可售` 反推，等于把两个独立事实压成一个数。REQ-003 允许按「房型 × 日期」下调可售（维修、封房），此时反推出来的占用会把"不可售"记成"已占用"，造成界面占用数失真、对账假告警、减房校验误拒。

反例（写进报告与界面说明）：总房量 10，某日零订单，因维修把可售调为 7 → 按现口径占用 = 3，实际占用 = 0。

## 2. 修正口径（唯一版本，全文照此改写）

| 概念 | 存放位置 | 语义 | 是否落库 |
|---|---|---|---|
| 总房量 | `room_type.totalRooms` | 该房型物理房间总数，只作上界 | 落库 |
| 可售间数 | `room_inventory.可售间数` | **当日挂牌可售总量**（已扣除维修/封房等不可售部分），`≤ 总房量` | 落库 |
| 已占用间数 | `room_inventory.已占用间数` | 当日被有效订单（待确认/已确认/已入住）占用的间数 | **落库（新增字段）** |
| 余量 | 派生 | `可售间数 − 已占用间数` | 不落库 |
| 区间可订上限 | 派生 | 区间内各日余量的**最小值** | 不落库 |

三条必须同时写进文档的规则：

1. **下单**：同一事务内 `可售间数 -= 间数` 且 `已占用间数 += 间数`（两者同时改，不可只改一个）；任一日改后可售 < 0 则整单回滚。
2. **取消 / 拒单 / 超时 / 停业回补**：同一事务内反向操作；以订单状态前置判断保证只回补一次。
3. **按日下调可售（维修/封房）**：只减 `可售间数`，**不动** `已占用间数`；只要改后 `可售间数 ≥ 已占用间数` 即合法。这是原口径无法表达的路径，必须写出来。

**减房（总房量 N → N′）校验**：`N′ ≥ 当前已占用间数` 才允许；允许时在同一事务内把该房型各日期行的 `可售间数` 减去 `N − N′`（占用不变），任一日为负则整体回滚。

**对账**：`room_inventory.已占用间数` ↔ Σ(状态∈{待确认,已确认,已入住} 的订单间数)。两条**独立来源**，不等即告警；对账仍不自动改库存。
