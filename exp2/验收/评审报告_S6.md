## 4. 新发现问题

**D-17（低-中，工程卫生）｜两份过程文档被整体 CRLF 化**

`git diff --numstat stage-5 HEAD`：`实验二_执行方案.md` **429 增 / 427 删**、`实验二_阶段与验收.md` **178 增 / 175 删**；但 `git diff -w`（忽略空白）只剩 **4 行 / 7 行**真实改动。实测两文件现在 **全部 CRLF**（429/429、178/178），而库里的历史版本是 LF。

这正是上一轮复验报告 §6.5 明令的"别再出现行尾整体翻转"（`exp2/.gitattributes` 是 `* -text`，不做自动归一化，谁写 CRLF 谁就整文件翻一遍）。后果：git log 上看起来改了上千行，其实只改了 11 行；终检若翻提交记录，会以为"AI 把基线文档重写了一遍"。

建议（约 5 分钟）：单独提交一次"行尾归一化"——把两份文档转回 LF 后提交，commit message 写明"仅行尾归一，无内容改动"，之后不再用 `Out-File`/`Set-Content` 写这两份文件。**不阻断交付，但建议在 S7 之前做掉**，否则后续报告正文的 diff 会继续被污染。

**D-18（低危，设计缺口）｜界面15 的"删除"没有说清能否物理删**

界面 15 有「编辑 / 删除」两个动作，但没有回答：**已被历史订单引用过的节假日区间，删了之后历史政策怎么追溯？** 建议改成"删除=停用（保留行、标 `已停用`）"，与审计"只追加"的思路一致；否则取消政策的历史判定会出现"当时是展会不可取消，现在查不到这条规则"的空洞。报告 4.x 写界面 15 时补一句即可。

**D-19（低危，仅影响打包）｜`UI界面/_src/` 不能进 zip**

手册规定的目录结构是 `UI界面/`（png）。`_src/`（`gen.py` / `style.css` / 17 份 HTML）是生成源，留在 git 里很好（可复现），但**不能打进 `实验2_241220024_陈一帆.zip`**，否则会被判"含多余文件"。S9 打包时只取 `界面01.png … 界面17.png`，打包脚本里显式过滤 `_src`。
