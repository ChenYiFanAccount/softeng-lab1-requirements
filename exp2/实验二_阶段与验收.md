## 2. 每阶段的验收方案

验收分两层，**先机械后人工**：
- **A 层（机械）**：`python 验收\check.py --stage N`，输出 `PASS/FAIL` 与逐条明细。不通过就不进下一阶段。
- **B 层（人工/评审 agent）**：按下表"评审检查点"逐条打分，任一"红线项"不满足即判该阶段未通过。

### S0 环境就绪

- **产出**：`D:\softeng-env\` 下 JRE 21、`plantuml.jar`、Graphviz `dot`、Python venv（Pillow、requests）；`验收\env_selftest.py`。
- **A 层**：`java -version`、`dot -V`、`java -jar plantuml.jar -version`、`python -c "import PIL, requests"` 四项全部有版本号；随后**用本机 PlantUML 渲染一张含中文的测试图**，PNG 存在、宽 > 200、非纯白。
- **B 层**：中文无方框/问号；渲染耗时 < 15s；不依赖外网即可出图（断网可渲染）。
- **红线**：中文变方框；必须先联网 Kroki 才能出图（则后续塌方）。

### S1 基线与口径冻结

- **产出**：`设计基线/01–03` 定稿、`验收\check.py`、口径卡（本文件 §0）冻结；`docs` 内不再有旧口径残留。
- **A 层**：`python 验收\check.py --stage 1` 共 43 项全 PASS——①27 条 REQ 每条都有"模块+UML+界面+报告章节"落点、编号连续、界面号都能在 H 节找到、01 与 02 的 REQ→模块双向一致；②状态转换 8 条（01 表 / 执行方案 C 表 / 口径卡三处同数）；③数据表 12 张且含 `booking_night`；④界面 01–17 齐全、每张标模块、M1–M9 无缺口、界面 15/16/17 已拆开；⑤类图 13 + 3 + 3 且含 `totalRooms`；⑥禁用词零命中（"7 条转换""11 张表""15 张界面""禁止反向箭头""3.13.16""11-14 23:59""净剩余""总房量 − 可售间数"）+ 口径卡 5 项自洽 + UML 组数 9；⑦库存三查：`room_inventory` 同时有可售与已占用并注明落库、03 §5 余量公式为「可售 − 占用」、02 §5 减房判据用"已占用"。

## 3. 统一验收机制

1. **每阶段收尾固定动作**：`git add -A && git commit`（信息前缀 `[S2]` 等）→ `git tag stage-N` → 跑 `python 验收\check.py --stage N` → 把标签名 + 脚本输出交给评审 agent。
2. **评审 agent 的输入契约**：阶段编号、`git show stage-N --stat`、`验收\check.py --stage N` 输出、本文件对应卡片。输出：逐条 PASS/FAIL + 返工清单（按严重度排序）。
3. **返工规则**：任一红线项 FAIL → 回退到该阶段重做，不带着缺陷进下一阶段；非红线项可记入"技术债清单"继续推进，S9 前必须清零。
4. **禁止跳阶**：S2/S3 依赖 S1 冻结的口径，跳过会导致全部图返工。
